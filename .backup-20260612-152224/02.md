## 1. 项目背景与目标

### 1.1 市场机会

> 引用 `01-竞品分析报告.md` §1（行业图谱与趋势）+ `00-用户访谈与痛点论证.md` §10（调研结论）

**W1 已校准**（2026-04-09 进一步修正，加入牛客体验）：

- 多面鹅最大弱点："复盘偏正向鼓励"（主差异化点）
- 多面鹅的"分公司风格"实测"微弱 + 需自设"，优面AI 的"开箱即用内置人设库"是**强差异化点**
- 牛客最大弱点："操作 bug 严重"（退出混乱 / JD 受限 / 不支持简历附件）
- 牛客"复盘完整 + 结构化"是**行业基线**（不是差异化，是入场券）
- **真正的机会窗口**：敢说真话 + 结构化拆解 + 基础设施稳定 + 兼容任意来源简历/JD（4 重组合）

行业数据（v0.2.3 已回填，引用 04-数据预估方案.md §2）：

- **TAM（潜在市场）**：3000 万人 × 5% AI 工具渗透率 = **150 万人**
- **SAM（可服务市场）**：200 万人 × 5% = **10 万人**（互联网 + Top 6 大厂）
- **SOM（可获取市场）**：6 个月内可获取 5000-30000 注册用户（v0.2.3 校准为 +20% 跨专业/研究生用户）
- **价格区间**：30-120 元/月（5 份访谈加权平均 **45 元/月**）
- **行业趋势**（引用 01-竞品分析报告.md §1.3）：
  1. 大厂在 AI 招聘上加速布局（字节收购多面鹅为标志事件）
  2. LLM 能力趋同，差异化集中在垂直场景与领域知识
  3. 求职社区 + AI 融合（牛客）成为新势力
  4. 垂直 AI 面试创业潮（面试狗等）瞄准细分场景
  5. C 端付费工具普遍采用"基础免费 + Pro 订阅"模式

- **现有竞品未满足的细分需求**（来自 00 §5 痛点 + 01 §5 差异化）：
  - 敢说真话 + 结构化拆解 + 基础设施稳定 + 兼容任意来源简历/JD（**4 重组合的机会窗口**）
- **优面AI 切入窗口**：跨专业 / 学术背景研究生细分（4/5 用户提及 P3）

## 4. 功能详述

### 4.1 模块 1：JD 解析

#### 4.1.1 用户故事

> 作为求职者，我希望输入目标 JD 后，能快速知道这个岗位的核心能力要求、公司风格、面试可能侧重点。

#### 4.1.2 流程图

```
[输入 JD 文本/链接] → [NLP 解析] → [岗位画像输出]
                                    ├─ 岗位类型（产品/运营/...）
                                    ├─ 职级（实习/校招/...）
                                    ├─ 核心能力词云
                                    └─ 公司风格标签
```

#### 4.1.3 功能点列表

- 支持纯文本输入
- 支持主流招聘平台链接（BOSS / 拉勾 / 实习僧）自动抓取
- 解析结果可视化（卡片 + 词云）
- 一键"用此 JD 定制简历"
- 一键"用此 JD 开始模拟面试"

#### 4.1.4 边界与异常

- 输入非 JD 文本：提示"看起来不是岗位描述，请检查"
- 解析失败：降级为关键词提取 + 人工补充
- 公司不在 Top 6：标记为"通用风格"，不提供差异化模拟


![02_模块1_JD：JD 解析详细流程](05-功能流程图/02_模块1_JD.png)

### 4.2 模块 2：简历定制

#### 4.2.1 用户故事

> 作为求职者，我希望能基于目标 JD 自动调整简历，让 HR 觉得"这简历就是为这个岗位写的"。

#### 4.2.2 流程图

```
[上传基础简历 PDF / 在线表单填写] → [JD 解析结果联动]
                                       ↓
                            [匹配度评分（0-100）]
                                       ↓
                  [改写建议（亮点高亮 / 经历重排 / 关键词补齐）]
                                       ↓
                              [定制版简历预览]
                                       ↓
                            [下载 PDF / 同步到模拟面试]
```

#### 4.2.3 功能点列表

- 支持 PDF 上传 / 在线表单填写 / 从主流招聘平台导入
- JD-简历匹配度评分（多维度：关键词 / 经历 / 技能）
- 自动改写建议（用户确认后应用）
- 定制版简历下载
- 一键"用此简历开始模拟面试"

#### 4.2.4 边界与异常

- PDF 解析失败：提示重新上传或手动填写
- 匹配度过低（< 30%）：提示"简历与 JD 差距较大，建议先补充经历"
- V1.0 不做 A/B 多版本测试

#### 4.2.5 经历包装与能力映射（W1 v0.2.3 新增，对应 P3）

**用户痛点**：4/5 用户提及"跨专业 / 学术背景难转化为产品经历"（小王·信管 / 小张·信管研二 / 小刘·统计 / 小李·商科）。

**产品功能**：

- 用户上传简历（含学术研究 / 跨专业经历）后，AI 帮转化为"产品岗视角"的能力映射
- 例如：
  - 信息系统研究 → 用户需求分析 + 业务流程优化能力
  - 数据分析项目 → 数据指标体系 + 数据驱动决策能力
  - 学术论文 → 系统思考 + 深度研究能力
- 输出：每段原始经历 + 对应的"产品岗能力标签" + 面试话术建议
- 一键"用此映射开始模拟面试"

**边界**：

- 仅做"映射 + 话术建议"，不编造经历
- V1.0 仅支持产品岗映射（运营/技术 V2+）


![03_模块2_简历：简历定制 + 经历包装详细流程](05-功能流程图/03_模块2_简历.png)

### 4.3 模块 3：模拟面试（核心模块）

#### 4.3.1 用户故事

> 作为求职者，我希望 AI 扮演"目标公司的真实面试官"，用这家公司的风格问我问题，遇到卡壳时能给我思路提示，并在结束后给我**诚实、有改进路径的结构化反馈**。

#### 4.3.2 流程图（W4 D6 升级：5 阶段 → 6 阶段）

```
[P02 选择公司 + 岗位 jobType（intern/campus）] → [AI 面试官人设匹配]
                                    ↓
                            [阶段 1 · 开场 - fixed]
                            AI：你好，欢迎参加 {company} 产品岗的 1 面面试。
                            请先用 2-3 分钟做一个自我介绍...（{company} 占位符动态替换）
                                    ↓
                            [阶段 2 · 简历深挖 - ai_resume_jd]
                            ⭐ M3 结合【简历 + JD】生成 1 个定制化追问
                            必须引用简历具体细节（项目/数据/角色）
                                    ↓
                            [阶段 3 · 专业问题 - bank]
                            ⭐ 30 道专业题库 RAG（按 stage+company 加权）
                            + M3 仅填 ${var} 占位变量（不改写题干）
                                    ↓
                            [阶段 4 · 开放性问题 - ai_open]
                            ⭐ M3 生成 1 个行为面试题
                            （团队协作/抗压/失败反思/价值观/跨界 之一）
                                    ↓
                            [阶段 5 · 实习/薪资 - logistics]
                            ⭐ 按 jobType 动态区分：
                              - intern 问
                                  你最快什么时候能开始实习？一周能到岗几天？预计能持续多长时间？
                              - campus 问
                                  你对薪资有什么样的预期？
                                    ↓
                            [阶段 6 · 反问环节 - reverse]
                            AI：面试接近尾声了。你有什么问题想问我的吗？
                            （引导用户问 1-2 个深度问题）
                                    ↓
                  [6 维雷达图 + 考点分析 + 回答分析 + 诚实反馈]
                  （产品感/逻辑/表达/案例/反问/抗压）
```

**与 5 阶段版的关键差异**：
- 阶段 2 由"题库固定"改为 M3 实时生成（提升相关性）
- 新增阶段 4 开放性问题（独立于专业问题，考察综合素质）
- 阶段 5 由"业务考察"拆分为"实习/薪资"，按 jobType 区分文案（v0.7 关键升级）
- 阶段 6 由"AI 扮演候选人"反问改为"引导候选人向面试官反问"（更真实）
- 整场固定为 6 主问 + 0-2 次追问（每主问），告别 5 题老版

**questionType 字段定义**（新增 v0.7）：
- `fixed` 固定文本
- `ai_resume_jd` M3 结合简历+JD 生成
- `bank` 30 道题库 RAG + M3 填变量
- `ai_open` M3 生成行为面试题
- `logistics` 按 jobType 区分（intern/campus）
- `reverse` 引导用户反问

#### 4.3.3 功能点列表（W4 D6 升级：6 阶段 · M3 全流程 · 题库 + jobType）

**⭐ 6 阶段面试流程**（v0.7 关键升级）：
1. **阶段 1 · 开场（fixed）** — AI 固定文本，含 `{company}` 占位符动态替换
2. **阶段 2 · 简历深挖（ai_resume_jd）** — ⭐ M3 结合候选人简历 + 岗位 JD 实时生成 1 个定制化追问
3. **阶段 3 · 专业问题（bank）** — ⭐ 30 道专业题库 RAG（按 stage+company 加权） + M3 仅填 `${var}` 占位变量
4. **阶段 4 · 开放性问题（ai_open）** — ⭐ M3 生成 1 个行为面试题（团队协作/抗压/失败反思/价值观/跨界 之一）
5. **阶段 5 · 实习/薪资（logistics）** — ⭐ 按 jobType 动态区分：intern 问时间，campus 问薪资
6. **阶段 6 · 反问环节（reverse）** — 引导候选人向面试官反问（不再"AI 扮演候选人"）

**⭐ jobType 区分**（v0.7 关键升级）：
- P02 页面"岗位"下拉框新增 `产品经理（校招）` / `产品经理（实习）` 选项
- 状态保存到 `p07State.jobType`（`campus` / `intern`）
- 阶段 5 根据 jobType 自动选择文案
- **设计意义**：实习 vs 校招的关注点完全不同（实习问"什么时候能来"，校招问"薪资预期"），不能混为一谈

**⭐ 题库 30 道 + M3 定制化**（v0.7 升级）：
- 规模：30 道专业题（按 stage 分布：开场 4 / 实习深挖 6 / 项目深挖 6 / 业务考察 10 / 收尾反问 4）
- 题源：4 家公司公开面经（牛客/小红书/知乎/脉脉）+ 5 份用户访谈 + PRD §5.2 公司画像
- 题库位置：`data/p07-question-bank.json` + `data/p07-question-bank.js`（内联版，规避 file:// CORS）
- RAG 检索：`modules/questionBank.js`（按 stage + company 加权，Top 1）
- M3 填变量：`modules/questionCustomizer.js`（prompt 严格约束"不重写题干，只填占位变量"，节省 75% token）
- 降级链：M3 正常 → 返回 JSON；M3 非 JSON → 正则提取 + 手动替换；M3 完全失败 → 启发式兜底 `[需追问]`
- **UI 溯源完全隐藏**：不显示"📚 来自题库"标签，避免破坏沉浸感

**配置项**（P02 / P06）：
- 公司（4 选 1：字节 / 腾讯 / 美团 / 小红书）
- 岗位 jobType（2 选 1：campus 校招 / intern 实习）
- 轮次（1 面 / 2 面）
- ⭐ **压力级别**（W1 v0.2.3 新增：温和 / 标准 / 字节式压力）

**实时聊天对话**：
- 语音转文字 / 纯文本
- AI 面试官头像 + 气泡（拟人化）
- 支持"实时打断 / 追问"（AI 风格化反应）
- 状态机驱动：idle（输入态）→ analyzing（分析态）→ feedback（反馈态）

**⭐ AI 提示回答**（W1 新增）：
- 用户卡壳超过 30 秒，问题下方自动出现"💡 思路提示"按钮
- 点击后给出思考框架（不直接给答案）
- 整场最多 1 次

**结束页 · 多维结构化反馈**（P08）：
- **6 维雷达图**（产品感 / 逻辑 / 表达 / 案例 / 反问 / 抗压）
- **考点分析**：每道题考察的核心能力点
- **回答分析**：候选人的具体表现
- **诚实反馈**（敢说真话核心）：优缺点并陈，给出可执行改进建议
- **3 条关键改进建议**：具体到"下次回答 X 类问题时，先说 Y，再展开 Z"
- **改进资源**（W1 v0.2.2 新增考点 + 回答分析，对标牛客的"完整"基线）

**历史记录自动归档**（模块 4）：
- 对话实时同步到云端（每条消息 < 1s）
- 自动生成复盘档案（P09 / P10）

#### 4.3.4 边界与异常

- 网络断开：本地缓存对话，恢复后继续
- 用户长时间未回复：AI 主动追问；超过 30 秒仍无回应，弹出"AI 思路提示"按钮
- 反馈生成超时：分阶段展示，先出分数后出建议
- 敏感内容：合规过滤
- **【W1 新增】用户主动退出**：用户说"结束"或点击退出 → AI 确认"好的，本次面试到此结束，是否保存并查看反馈？" → 用户确认 → 进入反馈页（**解决多面鹅"说再见循环"问题**）
- **【W1 新增】自动保存**：对话实时同步到云端（每条消息 < 1s），面试结束任何时候都不会丢（**解决"用户担心是否保存"问题**）
- **【W1 新增】反馈必须诚实**：禁止"全是鼓励 / 流于表面"，必须优缺点并陈，给出可执行改进建议（**核心设计原则**）

#### 4.3.5 设计原则（W1 v0.2.2，基于多面鹅 + 牛客体验）

基于多面鹅 W1 体验（2026-04-08）+ 牛客 W1 体验（2026-04-09），确立以下 **5 条不可妥协** 的设计原则：

1. **反馈必须诚实（敢说真话）**
   - 禁止"全是鼓励 / 流于表面"
   - 必须优缺点并陈，给出可执行的改进建议
   - 直接打中多面鹅最大弱点"复盘偏正向"
2. **反馈必须结构化完整（行业基线）**
   - 5 维雷达图 + 考点分析 + 回答分析（**W1 v0.2.2 新增**，参考牛客的"完整"基线）
   - 复盘"完整 + 结构化"是入场券，不是差异化
3. **平衡行为面试与产品知识考察**
   - 多面鹅的缺点："挖掘简历过多，产品知识考察少"
   - 优面AI 应保持 1:1 比例（行为面试 : 产品/业务知识）
4. **保留 AI 提示回答**
   - 多面鹅已有此功能，缺则劣势
   - 卡壳时给出"思路提示"，但不直接给答案
5. **优雅退出 + 自动保存 + 0 bug（W1 v0.2.2 强化）**
   - 解决多面鹅"说再见循环"和"担心是否保存"（多面鹅痛点）
   - **绝对避免牛客式 bug**："回答完无法识别结束 / 退出后仍生成报告"（牛客痛点）
   - 用户说"结束"→ AI 明确确认 → 一键保存 → 进入反馈页，**状态全程清晰**
6. **压力模拟能力（W1 v0.2.3 新增，对应 P7）**
   - 用户痛点：3/5 提及"面试紧张 / 被追问时慌"（小刘 / 小张 / 小陈）
   - 字节式"压力测试型"人设：**节奏快 + 连环追问 + 挑战判断**
   - 用户可选"压力级别"（温和 / 标准 / 字节式）
   - 配合"AI 提示回答"功能，卡壳时给思路

## 5. 大厂面试官人设库（设计规范）

### 5.1 覆盖范围

- **公司**：字节/腾讯/阿里/快手/美团/小红书/拼多多（V1.0 仅 3 选 1 落地）

**W1 校准**（基于多面鹅体验，2026-04-09 修正）：

- 多面鹅的"分公司风格"差异**实测为"微弱"**——需要用户自己设置面试风格才有
- 优面AI 的差异化点从"同维度但更深"**升级为"开箱即用 vs 用户自设"**的产品体验差异
- 策略：内置结构化人设库（4 维：开场 / 追问 / 关注点 / 红线词），用户打开即用，不需自设

### 5.2 内容维度（基于 W1 访谈真实画像）

| 维度 | 字节产品 | 腾讯产品 | 美团产品 | 小红书产品 |
| --- | --- | --- | --- | --- |
| **面试风格** | 压力测试型，节奏快，连环追问 | 系统思考型，注重底层逻辑 | 业务落地型，关注商业化 | 内容感知型，看重网感 |
| **开场风格** | 直接、自我介绍打断 | 温和、寒暄多 | 直接、问业务 | 亲切、聊社区氛围 |
| **追问风格** | 追问到底、压力测试 | 引导式、不打断 | 追问 ROI 细节 | 偏业务、案例多 |
| **关注点** | 商业 sense、ROI、数据驱动、增长逻辑 | 用户需求定义、思考过程、判断依据 | ROI、核心指标、业务流程 | 用户洞察、内容生态、创作者运营 |

### 5.3 内容生产流程

1. **采集**：公开面经（牛客/小红书/脉脉）+ 朋友内推的内部信息 + 自己的面试体验
2. **结构化**：按 4 个维度（开场/追问/关注点/红线）整理
3. **测试**：让真实面过该公司的人 review 一致性
4. **迭代**：每季度根据新面经更新

### 5.4 与多面鹅 + 牛客的差异化（W1 v0.2.2）

| 维度 | 多面鹅 | 牛客 | 优面AI |
| --- | --- | --- | --- |
| 分公司风格 | 微弱（需用户自设） | 微弱 | **开箱即用 + 4 维结构化**（开场/追问/关注点/红线） |
| 题目类型 | 简历深挖偏多 | 偏通用 | 行为面试 + 产品/业务 1:1 平衡 |
| 反馈完整度 | 不完整 | 完整（雷达图 + 考点 + 回答） | 完整（5 维 + 考点 + 回答 + 改进建议） |

## 6. 非功能需求

### 6.1 性能

- 首屏加载 < 2s（4G 网络）
- 模拟面试对话响应 < 1.5s
- 反馈报告生成 < 10s
- **W1 新增**：自动保存延迟 < 1s/条（解决"用户担心是否保存"）

### 6.2 安全

- 用户数据加密存储（AES-256）
- 对话脱敏（不保存个人敏感信息到训练集）
- 简历文件存储隔离

### 6.3 合规

- 遵循个保法（用户授权 + 数据可删除）
- 不提供"保过/内推"等虚假承诺
- AI 生成内容标识（按监管要求）
- 录音 / 录像需用户明确授权

## 11. AI 能力附录（v2.1 · 接入 MiniMax-M3）

> 本附录是 02-PRD 的"产品灵魂"——讲清**AI 怎么工作、怎么保证敢说真话、怎么限流降级、怎么控制成本**。
> 关联文件：`config.js`（API 配置）· `llm-integration.js`（LLM 调用封装）· `llm-hooks.js`（页面钩子）

### §11.1 设计目标（3 条不可妥协）

1. **敢说真话**：拒绝"鼓励式反馈"，每条反馈必须**优缺点并陈**（避免多面鹅式"偏正向"陷阱）
2. **结构化完整**：6 维评分（产品感/逻辑/表达/案例/反问/抗压）+ 考点分析 + 回答分析 + 改进建议（行业基线 + 差异化）
3. **std_dev 监控**：5 维评分标准差 > 1.5 自动告警，避免"全是 80+"的反馈通胀

### §11.2 模型选型对比表

> **主力：MiniMax-M3**（v0.6 W4 升级，从 GPT-4 改为 M3，理由：成本可控 + 中文稳定 + 合规风险低 + 创新定位）

| 模型 | 角色 | 中文能力 | 推理深度 | JSON 稳定性 | 单价（输入/输出 元/百万token） | 延迟（首token） |
| --- | --- | --- | --- | --- | --- | --- |
| ⭐ **MiniMax-M3** | **主力** | 5/5 | 4/5 | 4/5 | 约 ¥0.8 / ¥2.0 | ~1.5s |
| 通义千问 Qwen-Plus | 备选 1 | 4/5 | 4/5 | 4/5 | ¥4 / ¥12 | ~1.0s |
| 模板降级 | 兜底 | - | - | - | 0 | 即时 |

**推荐组合**：**M3 主力** + **Qwen-Plus 备选**（API 限流时切换）+ **模板降级**（全部失败时本地 fallback）。理由：
- M3 在敢说真话 / 中文理解 / JSON 输出 3 个核心维度都达到 4-5 分
- 单价仅为 GPT-4 的 1/30，毛利率 95%+
- 备选 1 家足够（再多家增加维护成本但边际收益低）

### §11.3 Prompt 模板库（5 套 · 全部 M3-optimized）

#### P1 · 4 家人设 system prompt（模块3 模拟面试）

**字节跳动**（详见 `llm-integration.js` PERSONAS['字节']）：
- ⚡ 节奏快，1-2 句话内必追问
- 📊 数据驱动，开口就要"数据基线 / 对比对象"
- 🔥 压力测试，连续追问 3 次以上
- 🚫 红线：禁止"我觉得 / 大概 / 差不多"

**腾讯**：🧠 系统思考 + 追问"为什么"+"为什么"
**美团**：💼 业务落地 + 💰 商业化思维 + 📈 数字敏感
**小红书**：🌸 内容感知 + 💕 用户洞察 + 🎨 感性表达

#### P2 · 6 维评分 system prompt

评分锚点：60=明显不足 / 70=勉强达标 / 80=达到校招 bar / 90=超出预期

#### P3 · 3 压力级别 prompt

- **温和**：0-1 次追问，适合初次体验
- **标准**：1-2 次追问，逐步深入（默认）
- **字节式**：连续追问 3 次以上，犀利直接，**不轻易放过模糊回答**

#### P4 · 诚实反馈 prompt（敢说真话核心）

```
HONEST_FEEDBACK_PROMPT = "你是 {company} 的产品面试官...
【敢说真话要求】
1. 优点和不足并列（必须同时 2-3 个）
2. 数据基线（评分必须有'为什么是这个分'的依据）
3. 可执行改进（具体到'下次回答 X 类问题时，先说 Y，再展开 Z'）
4. 避免空泛（禁止'回答不错 / 表达流畅'等无信息反馈）"
```

**完整 prompt 见 `llm-integration.js` `HONEST_FEEDBACK_PROMPT` 变量（约 1500 字符）**

#### P5 · 经历包装 prompt（模块2 P3 跨专业）

```
PACKAGE_EXPERIENCE_PROMPT = "你是产品经理求职辅导专家...
【严格约束】
1. 不编造事实（只能基于真实经历做能力映射）
2. 聚焦可迁移能力
3. 每段经历 3-5 个标签
4. 每个标签 1 句转化说明"
```

#### §11.3.6 题库架构（30 道 + AI 定制化）· v1.0

> **W4 D5 升级**：P07 主问题从"5 道硬编码"升级为"30 道专业题库 + M3 实时填变量定制化"的混合模式。
>
> **核心思路**：**主问题结构由题库保证**（专业度），**问题个性化由 M3 保证**（相关性）。
>
> **追问问题继续走 M3 实时生成**（从题库 followup_angles 选角度 + M3 二次生成）。


> **W4 D6 升级**：P07 流程从 5 阶段升级为 6 阶段，本节说明 P07 6 阶段与题库 5 stage 字段的映射关系。

**P07 6 阶段 → 题库 stage 映射表**：

| P07 阶段 | questionType | 题库 stage（映射） | 来源 | 是否走 M3 |
| --- | --- | --- | --- | --- |
| 1. 开场 | `fixed` | - | 固定文本 | ❌ |
| 2. 简历深挖 | `ai_resume_jd` | 实习深挖（fallback） | M3 实时生成 | ⭐ 是 |
| 3. 专业问题 | `bank` | 业务考察 | 题库 RAG + M3 填变量 | ⭐ 是 |
| 4. 开放性问题 | `ai_open` | 项目深挖（fallback） | M3 实时生成 | ⭐ 是 |
| 5. 实习/薪资 | `logistics` | - | 按 jobType 区分文案 | ❌ |
| 6. 反问环节 | `reverse` | - | 固定文本 | ❌ |

**映射实现**（`p07RenderCurrent` 内部）：

```js
const stageMap = {
  '简历深挖': '实习深挖',
  '专业问题': '业务考察',
  '开放性问题': '项目深挖'
};
const bankStage = q.bankStage || stageMap[q.stage] || q.stage;
```

**为什么不改题库 stage 字段**：
- 题库已 30 道，stage 字段保持稳定向后兼容
- 6 阶段是产品展示层概念，题库 stage 是数据层概念
- 通过映射表解耦，未来扩到 60 道题库时只改 stageMap
**题库数据**（`data/p07-question-bank.json`，~20KB）：
- 规模：30 道（开场 4 + 实习深挖 6 + 项目深挖 6 + 业务考察 10 + 收尾反问 4）
- 分布：字节 17 / 腾讯 16 / 美团 16 / 小红书 17
- 含 template_vars 的题：14 道（需定制化）
- 公司特色题（< 4 公司标签）：18 道

**题库 Schema**：

```json
{
  "id": "q013",
  "stage": "项目深挖",
  "company_tags": ["字节"],
  "type": "项目-字节",
  "difficulty": "hard",
  "text": "你提到 ${project_name} 覆盖 ${user_count} 用户...",
  "template_vars": ["project_name", "user_count"],
  "followup_angles": ["你说月 GMV 是 ${monthly_gmv}...", "..."],
  "evaluation_focus": ["增长黑客", "陌生人场景", "渠道 ROI"]
}
```

**RAG 检索算法**（`modules/questionBank.js`）：

```js
score(q) = (stage匹配 ? 10 : 0) + (company命中数 × 5) + (medium ? 1 : 0) - (通用4公司 ? 1 : 0)
```

→ 取 Top 3 中随机 1 道（避免每次固定）。

**M3 填变量**（`modules/questionCustomizer.js`）：

- 输入：题库模板 + 候选人简历 + 目标公司
- 输出：`.filled_text`（填好变量的问题文本）+ `.vars`（变量值）
- prompt 严格约束：**不重写题干，只填 ${var} 占位**（节省 75% token）
- 响应时间：~1-2s
- 单次成本：~¥0.0002（vs 完整改写 ~¥0.0008）
- 缓存：按 `qid + resumeHash` 缓存，避免重复定制

**降级链**（3 级）：

1. M3 正常 → 返回 JSON
2. M3 返回非 JSON → 正则提取 `vars`，filled_text 用原模板 + 变量手动替换
3. M3 完全失败 → 启发式兜底（用简历第一行 + 数字匹配）→ 返回 `[需追问]` 占位

**UI 溯源**：

- **完全隐藏题库 ID**（不显示"📚 来自题库"标签）
- 演示话术："我们的题库有 30 道专业题（来源：4 家大厂真实面经 + 5 份用户访谈），AI 在每道题上根据候选人简历做定制化填充——不是简单替换变量，而是结合候选人提到的具体项目/数据/经历。这样既能保证题目专业度，又能让候选人感觉'这道题是为我出的'。"

**文件结构**：

```
data/p07-question-bank.json   (30 道题)
data/p07-question-bank.js     (内联版本，规避 file:// CORS)
modules/questionBank.js       (RAG 检索)
modules/questionCustomizer.js (M3 填变量)
```

### §11.5 反馈质量保障机制

1. **std_dev 监控**（沿用 04 §1.3）：5 维评分标准差 < 1.0 触发告警
2. **人工抽检**：每 100 场抽 3-5 场做人工评分对比
3. **"反馈偏正向"自动兜底**：当 std_dev < 1.0 触发**二次 prompt 强制重评**：
   ```
   你的上一条反馈被认为"过于鼓励 / 缺乏具体不足"，请用更直接的语言重新评估，
   明确指出候选人最严重的 3 个问题，并给出可执行改进建议。
   ```
